1. 전체 흐름
로그인 -> 오늘 방문 -> 예정 방문 상세 -> 서비스 시작 -> 돌봄 중
돌봄 중 -> 쉬기 시작 -> 휴게 -> 다시 시작 -> 돌봄 중
돌봄 중/휴게 -> 종료 확인 -> 종료 결과 -> 방문 기록 -> 기록 상세
돌봄 중/기록 상세 -> 현장 사유 선택 및 메모 -> 저장 -> 이전 화면
예정 방문 -> 일정 변경 요청 -> 승인 대기
기록 상세 -> 기록 정정 요청 -> 승인 대기 (원본 시간 유지)
요청함 -> 기관 질문 -> 답변 -> 답변 완료 -> 요청함
요청함 -> 내가 보낸 변경 요청 -> 처리 상태
내 정보 -> 권한/기록 확인, 도움 안내, 로그아웃

3. 공통화 및 실제 동작 보완
- 반복되는 버튼/입력창/카드/알림/상태/하단 메뉴를 공통 컴포넌트로 구현.
- 원본의 다양한 프레임 높이를 강제하지 않고 내용 길이별 세로 스크롤 적용.
- 방문 종료는 확인 화면을 거치며 계속 활동하기로 취소 가능.
- 수정 요청은 요청 값/사유를 받되 원본 방문 시각을 직접 변경하지 않음.
- 사유 필수값과 기본 시간 형식 검사 추가.
- 답변 후 요청함의 답변 상태와 알림 건수 변경.
- 기록 상세에 저장한 현장 사유 반영.
- 날짜 이동 시 준비된 2026-03-12 외 날짜는 빈 기록 상태 표시.
- 기관 연락처/회원가입 후속 화면이 없으므로 임의 전화번호/가입 기능 대신 안내창.
- 진행 중 방문이 있으면 로그아웃 안내 후 중단.

4. 원본 기획에서 확인할 사항 (정적 화면에는 원본 데이터 유지)
- 제품 명칭: 이전 대화의 ‘동행이음’과 최신 프레임의 ‘돌봄이음’이 다름.
- 인증: 이전 기획은 SMS 인증, 최신 프레임은 휴대폰 번호+비밀번호.
  정적 화면만 구현했으며 실제 인증 정책 변경을 뜻하지 않음.
- 위치: 예정 방문은 ‘서울시 강서구 화곡동’, 기록은 ‘아리역로 37’.
- 시간: 돌봄 누적 2시간32분/휴게0분 화면 뒤 휴게 시작11:00 예시는
  동일 방문의 실시간 경과 시나리오로는 맞지 않음. 화면별 고정 예시로 유지.
- 예정 일정과 종료 기록이 모두 2026-03-12의 동일 이용자로 표시됨.
  원본 시연용 예시를 그대로 사용하며 실제 업무 데이터 통합은 추후 필요.
- ‘움직임 시험 기능 확인 중’은 정적 표기이며 실제 센서 지원 여부를 확인하지 않음.
- 원본의 작은 보조문구/녹색 텍스트 대비는 향후 접근성 검사 대상으로 남음.
- 생략된 회원가입 후속/최초 동의/권한 요청 화면은 이번 Figma 범위에 없음.

5. 검증
- 20개 프레임의 디자인 컨텍스트/스크린샷을 확인하여 구현.
- 각 화면의 렌더링 이미지와 Figma를 비교.
- 작은 화면(320x640)에서 글자 1.5배 확대 및 스크롤 넘침 검사.
- 로그인 진입, 시작/휴게/복귀/종료, 사유 저장, 정정 요청/원본 유지,
  기관 답변 제출에 대한 위젯 테스트.
- 웹 릴리스 빌드 및 로컬 HTTP 응답 확인. 브라우저 자동 조작은 브라우저/네이티브 연결 도구가 사용 불가하여 실행하지 못함. 화면 비교는 Flutter 실제 렌더링 PNG로 수행.
- 실기기 GPS/배터리/실제 기관 전송 검증은 정적 프론트 범위에 포함되지 않음.
