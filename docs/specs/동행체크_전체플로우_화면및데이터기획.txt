01. 처음 보는 사람에게 설명하는 서비스
────────────────────────────────────────
“활동지원사는 방문 시작과 휴게·종료를 앱에 남깁니다. 인터넷이 안 돼도 휴대폰에
저장합니다. 기관은 확인이 필요한 기록이 있을 때 그 이유와 현장 설명을 함께 봅니다.”

예시 A | 정상 방문
① 기관 담당자가 김지원 활동지원사에게 이용자 가의 09:00~13:30 방문을 배정한다.
② 지원사는 [서비스 시작]을 누르고, 11:00에 [쉬기 시작]을 누른다.
③ 11:30에 [다시 시작], 13:30에 [방문 종료]를 누른다.
④ 앱은 방문 전체 4시간 30분 / 휴게 30분 / 돌봄 기록 4시간을 보여준다.
⑤ 기관 화면에 종료 기록이 표시된다. 확인 사건이 없으면 쌍방 답변을 요구하지 않는다.
‘돌봄 기록’은 앱이 계산한 기록 시간이며 실제 돌봄의 증명·급여·결제액이 아니다.

예시 B | 확인이 필요한 방문
① 유효한 위치 기록에서 평소 유사 방문과 다른 외출 구간이 발견된다.
② 시스템이 담당 관리자에게 이유·구간·기록 품질을 붙여 알린다.
③ 관리자가 “이 시간대에 어떤 지원을 하셨나요?”라는 구체적 질문을 보낸다.
④ 지원사는 해당 구간에서 [병원 동행]을 선택하고 필요한 내용을 짧게 작성한다.
⑤ 관리자가 기관 답변과 검토 결과를 작성한다.
⑥ 지원사 답변과 기관 답변이 모두 서버에 저장돼야 검토 완료가 가능하다.
정상 외출을 자동으로 부정수급이라고 판단하지 않는다.

예시 C | 통신이 끊긴 방문
① 미리 받은 방문 정보 또는 내려받은 이용자로 임시 방문을 시작한다.
② 시작·휴게·종료와 현장 설명은 휴대폰에 저장한다. 위치는 측정에 성공한 경우만 저장한다.
③ 종료하면 통신 여부와 관계없이 위치 기록을 멈춘다.
④ 연결 복구 후 서버가 기록을 받으면 관리자 화면이 갱신되고 분석이 실행된다.
인터넷이 없을 때 서버 AI가 실시간으로 알림을 보내는 것은 불가능하다.

02. 이번에 확정한 운영 정책
────────────────────────────────────────
P01 [확정] Android와 iOS 모두 지원한다. 실제 백그라운드 동작은 각각 시험한다.
P02 [확정] 여러 기관이 서비스를 사용한다. 지원사는 동시에 한 기관에만 소속된다.
P03 [확정] 지원사가 먼저 회원가입하고 기관이 해당 지원사를 등록한다.
P04 [확정] 관리자/기관이 일정을 변경한다. 지원사는 변경을 요청한다.
P05 [확정] 등록된 이용자에게 임시 방문을 만들어 시작할 수 있다. 신규 이용자 직접 입력은 제외.
P06 [확정] 위치 권한이 없어도 시간을 기록한다. 위치 미확보를 부정 징후로 취급하지 않는다.
P07 [확정] 지원사가 사유를 적어 정정을 요청하고 관리자가 승인해야 기록에 반영한다.
P08 [확정] AI 이상 징후가 발견되면 알림을 제공한다.
P09 [확정] 확인 사건은 지원사와 기관의 답변이 모두 필요하다.
P10 [확정] 해당 기관 담당 관리자가 기관 답변을 작성한다. 별도 상위 승인자는 두지 않는다.
P11 [확정] 핵심 기능부터 구현한다. 단순 시연 화면만으로 AI가 구현됐다고 표시하지 않는다.
P12 [기존 방향] 이용자에게 앱 설치·QR·생체인증·휴게 승인을 요구하지 않는다.
P13 [제안] ‘관리자’는 기관 담당 관리자를 뜻한다. 플랫폼 운영자는 기관 업무 담당자와 별도다.
P14 [확정] AI 알림은 담당 관리자만 수신한다. 지원사는 관리자가 검토 후 보내는 질문을 받는다.
P15 [제안] 시간 중복 같은 규칙 점검 알림도 별도 출처를 붙여 동일한 검토 절차에 연결한다.

03. 누가 무엇을 볼 수 있는가
────────────────────────────────────────
활동지원사
  본인의 현재 기관·배정 일정·본인 방문·본인 확인 요청만 열람.
  직접 가능: 시작/휴게/복귀/종료, 임시 일정 생성, 현장 설명, 정정 요청.
  직접 불가: 이용자 신규 등록, 일정 원본 변경, 기록 원본 수정, 타 지원사 경로 열람.
기관 담당 관리자
  자기 기관의 승인된 담당 범위에서 지원사·이용자·일정·방문·검토 사건 관리.
  가능: 지원사 등록, 일정 배정·변경, 정정 승인/반려, 설명 요청, 기관 답변과 검토 완료.
  타 기관의 이용자·직원·위치·답변을 조회할 수 없다.
이용자
  앱 조작 역할 없음. 앱 미사용이 개인정보 안내·처리 근거 확인의 면제를 뜻하지는 않는다.
플랫폼 운영자 [제안]
  기관 계정·서비스 오류 관리만 기본 허용. 상세 경로·현장 설명은 기본 열람 불가.
  장애 대응 접근은 별도 권한·기록을 남기는 절차를 후속 설계한다.

기관 연결 [제안 흐름]
회원가입 → 소속 미등록 → 지원사 본인 연결 코드 제시 → 기관이 코드로 등록 요청
→ 지원사가 기관명 확인 → 연결 완료 → 오늘 방문 열림.
기관이 임의로 계정을 찾아 붙이지 않도록 코드 및 본인 확인을 제안한다.
동시에 두 기관에 등록하는 요청은 차단하고 기존 소속을 먼저 정리하도록 안내한다.
기관 이동 시 이전 기관 기록을 새 기관에 복사하지 않는다. 과거 기록의 지원사 접근 범위는 미정.
소속 해제 시점·미전송 자료·미완료 사건 처리 절차는 실제 운영 전에 확정한다.

04. 전체 시스템 흐름
────────────────────────────────────────
지원사 앱: 회원가입 → 기관 연결 → 일정 수신 → 시작 → 휴게/복귀 → 종료 → 필요 시 답변
기관 웹:   직원 등록 → 이용자/일정 배정 → 진행 현황 → 확인 사건 → 질문/기관 답변 → 완료
휴대폰:    버튼·위치 이벤트 저장 → 전송 대기 → 서버 확인 응답 → 전송 완료 표시
서버:      사용자·기관 권한 검증 → 중복 제거 → 원본 저장 → 방문 상태 계산 → 분석 분기
분석:      위치 품질 분류 → 규칙/패턴 분석 → 확인 사건 생성 → 알림 → 사람의 검토

정상 기록은 저장으로 끝난다. 모든 방문에 답변 절차를 강제하지 않는다.
품질 불량은 위치 분석을 보류한다. 시간 데이터가 충분하면 시간 중복 규칙은 계속 검사한다.
일정 변경과 방문 기록 정정은 다른 업무다. 일정 수정만으로 과거 실제 기록을 바꾸지 않는다.

05. 상태를 섞지 않는 설계
────────────────────────────────────────
방문 상태: 예정 → 돌봄 중 ↔ 쉬는 중 → 종료.
  시작 전 일정 취소 가능. 진행 중 취소는 방문 종료 및 필요 시 정정 절차로 분리한다 [제안].
  휴게 중에도 [방문 종료]를 보조 메뉴로 제공한다. 종료 시점에 휴게 구간도 닫는다.
전송 상태: 기기 저장 → 전송 대기 → 전송 중 → 서버 저장 완료 / 재시도 필요.
위치 상태: 기록 중 / 휴게로 중단 / 종료로 중단 / 권한 없음 / 신호 불량 / 수집 지연.
검토 상태 [제안]: 확인 필요 → 질문 발송·지원사 답변 대기 → 기관 답변 대기 → 검토 완료.
  답변 불충분 시 추가 질문 가능. 추가 질문마다 답변 버전을 남긴다.
  미응답이면 대기 유지. 시간이 지났다고 자동 완료하지 않는다.
정정 상태: 요청 작성 → 제출 대기 → 승인 대기 → 승인 또는 반려.
임시 방문: 방문 상태와 별도로 ‘임시’ 표시. 기관 확인 상태는 방문 종료와 별개다 [제안].

화면 예: ‘방문 종료 / 전송 대기 / 위치 기록 중단’.
관리자 예: ‘마지막 수신 11:20 / 이후 상태 미확인’. ‘계속 돌봄 중’이라고 확정하지 않는다.
검토 완료 조건:
  해당 사건의 지원사 답변 + 기관 답변 + 검토 결과 + 승인 필요 정정 건 처리 완료.
기존 현장 사유가 사건에 해당하면 지원사가 [이 내용으로 답변]으로 재사용하도록 제안한다.
전화 버튼만 누른 것으로 답변 완료 처리하지 않는다. 통화 내용은 지원사가 확인 제출해야 한다 [제안].

06. 활동지원사 앱 와이어프레임 명세
────────────────────────────────────────
공통 레이아웃
  상단: 화면 제목·뒤로가기·필요한 기관명. 중앙: 한눈에 필요한 정보.
  하단: 현재 상태의 주 행동. [오늘 방문 / 기록 / 요청 / 내 정보] 하단 탐색을 제안한다.
  돌봄 중 화면에서는 불필요한 메뉴보다 진행 방문으로 돌아오는 행동을 우선한다.
  황색 주 버튼 + 진한 글자. 상태는 색뿐 아니라 문구·아이콘으로 구분한다.
  본문 18sp 안팎·버튼 높이 56dp 안팎을 디자인 출발값으로 삼고 확대 글씨/작은 폰에서 시험한다.
  숫자 키패드, 짧은 선택지, 큰 터치 영역. 긴 사유 입력은 ‘기타’일 때도 최소화한다.
  제출 직후 저장/전송 결과를 보여준다. 반복 누름으로 동일 이벤트를 두 번 만들지 않는다.
  아래 프레임 수는 화면 설계 단위이며, 사용자가 모두 순서대로 거치는 절차가 아니다.

M01 로그인·회원가입
  정보: 서비스명, 전화번호/인증 등 가입 수단, 쉬운 안내, 기관 문의.
  행동: [회원가입], [로그인]. 인증 방식·비용은 미정; 가상 인증을 실서비스 인증으로 간주하지 않음.
  다음: 신규는 M02. 기존 사용자는 연결 상태에 따라 M03 또는 M04.
  예외: 인증 실패·번호 변경·계정 복구 안내. 민감정보가 잠금화면에 노출되지 않게 한다.

M02 기록 안내·동의
  정보: 방문 중 위치·시각 기록, 휴게/종료 중단, 기관 열람, 보관·삭제 안내.
  행동: 필수 약관과 선택적 위치 관련 절차 구분, [확인하고 계속].
  상태: 위치 권한 거부 시 ‘시간만 기록 가능’. OS 권한은 앱 동의와 별개.
  다음: M03. 동의만으로 위치 수집 금지.

M03 기관 등록 대기·연결 확인
  정보: 본인 이름, 연결 코드, ‘아직 기관에 등록되지 않았어요’.
  행동: [코드 보여주기], [기관 연결 확인], [도움받기].
  다음: 기관명·연결 요청 확인 후 M04. 타 기관 소속 중이면 중복 연결 차단 안내.

M04 오늘 방문 — 홈
  상단: 현재 기관, 날짜, 미전송 건수(있을 때), 확인 요청 개수.
  중앙: 다음 방문 대상·예정 시간·상태의 큰 카드. 진행 방문이 있으면 최상단 고정.
  행동: [방문 상세], [임시 방문 등록], 요청 배너, 내 정보.
  다음: M05/M06/M15. 앱 재실행 시 진행 중 방문 진입을 우선.
  빈 상태: ‘오늘 배정된 방문이 없어요’ + 임시 방문/기관 연락.

M05 방문 상세 — 시작 전
  정보: 이용자 이름, 예정 시각, 예정 휴게, 등록 장소, 기관 메모, 위치 가능 여부.
  행동: 큰 [서비스 시작], 보조 [일정 변경 요청], [기관에 전화].
  확인: 잘못된 대상 시작 방지를 위해 대상 이름을 주 버튼 근처에 반복.
  다음: 시작 성공 시 M07. 버튼 중복 입력 방지.
  위치 없음: ‘시간만 기록합니다’ 안내 후 시작 허용. 주소 밖은 안내하되 자동 차단하지 않음 [제안].
  다른 방문 진행 중: 종료 또는 상태 정리 안내. 동시 방문 차단을 제안함.

M06 임시 방문 등록
  정보: 소속 기관 고정, 내려받은 등록 이용자 검색·선택, 예정 종료, 임시 방문 사유.
  행동: [등록하고 시작]. 임시 일정 생성과 방문 시작 성공 여부를 구분해 표시.
  다음: M07 ‘임시 방문’ 표시. 기관에는 임시 방문 목록 제공.
  오프라인: 내려받은 이용자만 선택; 기기에 없는 신규 대상은 등록 불가·기관 문의.
  추후 동일 정식 일정 배정 시 자동 중복 생성하지 않고 기관이 연결 확인 [제안].

M07 돌봄 중 — 핵심
  정보: 이용자·기관, ‘돌봄 중’, 시작 시각, 돌봄 누적시간, 휴게 누적시간, 전송 상태.
  행동: [쉬기 시작], [현장 사유 남기기], 아래 별도 영역 [방문 종료], [기관 연락].
  다음: M08/M09/M10. 휴게를 실제로 시작한 경우에만 상태 변경.
  통신 문제: ‘휴대폰에 저장 중이에요. 연결되면 전송할게요.’
  위치 미수신: ‘시간은 기록 중이에요. 위치를 확인하지 못했어요.’
  권한 없음: ‘위치 권한이 없어 시간만 기록해요.’ 세 상태를 구분한다.
  기관 변경/다른 방문 선택으로 현재 방문을 자동 종료하지 않는다.

M08 쉬는 중 — 핵심
  정보: ‘쉬는 중’, 휴게 시작·경과시간, ‘지금은 위치를 기록하지 않아요’.
  행동: 가장 큰 [다시 시작]; [기관에 도움 요청]; 보조 [방문 종료].
  다음: 복귀 M07, 종료 M10. 자동 복귀·자동 30분 차감 금지.
  휴게 중 오프라인에서도 기록·복귀 가능. 복귀 시 위치 권한 없으면 시간 기록만 재개.

M09 현장 사유 작성 — 선택
  정보: 대상 방문·시간 구간, ‘어떤 지원을 하셨나요?’
  선택: 병원 동행 / 장보기 동행 / 가사 지원 / 기타. 선택지 실제 사용어는 인터뷰로 보완.
  행동: 구간 수정, 짧은 메모, [저장]. 이용자의 병명·진료 상세 등 불필요한 정보는 요청하지 않음.
  다음: 원래 화면. 자동 측정값과 본인 입력을 분리 저장.
  오프라인: ‘휴대폰에 저장했어요’. 입력은 정상 방문 완료의 필수 요건이 아님.

M10 방문 종료 확인 — 작은 확인창
  정보: 이용자 이름·현재 시각, ‘방문을 종료할까요?’
  행동: [계속 기록], [종료]. 실제 버튼 처리 시각으로 종료 이벤트 생성.
  다음: M11. 단순 사유 미작성으로 종료를 막지 않는다.

M11 종료 결과
  정보: 전체 방문 구간, 돌봄 기록 시간, 휴게 시간, 위치 중단, 전송 결과.
  행동: [오늘 방문으로], [기록 확인], [기록 수정 요청].
  예외: “종료했어요. 연결되면 기록을 자동으로 보낼게요.” 종료 성공과 서버 전송을 분리.
  예시: 09:00~13:30 / 돌봄 4시간 / 휴게 30분 / 전체 4시간 30분.

M12 기록 목록·방문 기록 상세 (두 프레임)
  목록: 날짜·이용자·시간·전송·검토 상태. 본인의 기록만.
  상세: 시작/휴게/복귀/종료 시간줄, 현장 사유, 기관 질문, 원본·정정 표시.
  행동: [정정 요청], [현장 사유 추가], 관련 확인 요청 열기.
  지도는 보조 정보. 지도를 읽지 못해도 시간·상태를 이해할 수 있게 한다.

M13 일정 변경·기록 정정 요청
  정보: 변경 대상 명확히 표시. 예정 일정과 실제 기록을 탭/진입 경로로 구분.
  필드: 원래 값(읽기 전용), 요청 값, 사유(필수). 큰 시간 입력 도구.
  행동: [요청 보내기]. 다음: 요청 결과·승인 대기 화면.
  승인 전 원본 유지. 반려 이유와 재요청 가능 여부 표시.
  서버 수신 전에는 ‘승인 대기’ 대신 ‘요청 전송 대기’.

M14 요청함
  탭: 기관 확인 요청 / 내가 보낸 변경 요청.
  정보: 대상·구간·질문 요약·답변 필요 여부·보낸 시각·전송 상태.
  행동: 기관 질문 선택 → M15. 내가 보낸 변경 요청 → M13의 요청 상세/결과 상태.
  빈 상태: “답변할 요청이 없어요.”

M15 확인 요청 상세·답변
  정보: 기관명, 관리자 질문, 대상 방문, 확인 구간, 규칙/AI 확인 이유의 쉬운 설명.
  행동: [답변 작성], [기존 사유로 답변], [기록 정정 요청], [기관에 전화].
  필수: 사건에 대한 지원사 본인의 답변 제출. 정정 요청만 보냈다고 답변 완료 처리하지 않음.
  제출: ‘지원사 답변 제출 / 기관 검토 대기’. 전송 실패는 초안 유지·재전송.
  전화만 한 경우 제출된 답변 없음. 지원사 확인을 어떻게 받을지 운영 절차 검토 필요.

M16 내 정보·권한·도움
  정보: 이름, 소속 기관, 위치 권한, 알림 권한, 미전송 건수, 문의 번호.
  행동: 권한 설정 안내, 개인정보 안내, 계정 복구·기관 이동 문의.
  로그아웃/앱 삭제 안내: 진행 방문·미전송 건이 있으면 손실 위험과 조치 먼저 안내.
  GPS 허용을 반복 강요하지 않음. 권한 없이도 시간 기록 경로 유지.

필수 상태 변형 프레임
  M04 빈 일정 / M07 위치 불가 / M11 오프라인 완료 / M15 답변 전송 실패 /
  M13 반려 / M03 기관 중복 연결 / M08 확대 글씨 버전.
  iOS·Android 화면은 목적·문구를 같게 하되 권한 요청창은 각 OS 실제 동작을 따른다.

07. 관리자 웹 와이어프레임 명세
────────────────────────────────────────
공통: 상단 기관명·계정·알림. 왼쪽 메뉴는 현황 / 일정 / 방문 기록 / 확인 사건 /
      변경 요청 / 지원사·이용자 / 기관 설정.
      다른 기관으로 이동 가능한 일반 기관 계정을 만들지 않는다.
      지도 중심의 상시 감시 화면보다 확인할 업무 목록을 먼저 보여준다.

A01 관리자 로그인·기관 진입
  기관 계정으로 로그인, 자기 기관 홈으로 이동. 기관 개설/관리자 초대 절차는 미정.
  권한 없는 URL 직접 접근도 서버에서 거부한다.

A02 오늘의 현황 — 대시보드
  상단 필터: 날짜·담당자·기록 상태·검토 상태.
  첫 줄 카드: 예정 / 돌봄 중 / 쉬는 중 / 종료. 한 방문은 이 중 하나에만 포함.
  두 번째 카드: 확인 사건 / 지원사 답변 대기 / 기관 답변 대기 / 정정 승인 대기.
  ‘확인 사건’은 방문 건수와 다른 집계임을 표시. 하위 상태를 전체 합계와 중복 합산하지 않음.
  중앙 주요 표: 시각, 지원사, 이용자, 탐지 출처, 이유, 구간, 품질, 마지막 수신, 담당자, 상태.
  보조 표: 임시 방문과 기록 수신 지연. 경로 판단 보류는 부정 의심 건수에 넣지 않음.
  행동: 행 선택 → A06, 임시 방문 → A05, 정정 요청 → A08.

A03 지원사·이용자 관리
  지원사 탭: 등록 코드 확인, 연결 대기/활성/해제 상태, 담당자 배정.
  이용자 탭: 최소 식별정보, 등록 거주지, 담당 지원사, 활동 가능 범위 관련 메모.
  버튼: [지원사 등록], [이용자 등록], [담당자 변경].
  기관명이 다른 연결 요청은 막는다. 주소 변경 이력을 남겨 과거 방문을 새 주소로 재판정하지 않음.

A04 일정 달력·편집
  일/주 보기, 지원사별 시간 막대, 휴게 예정, 일정 충돌 안내.
  입력: 등록 이용자·지원사·날짜·시간·예정 휴게·기관 메모.
  예정 일정 충돌은 배정 경고이고 실제 방문 중복 사건과 구분.
  시작 후 일정 변경은 새 버전으로 남긴다. 실제 기록 원본은 바꾸지 않는다.
  지원사 변경 요청 승인/반려 → 앱에 새 일정 수신 여부 표시.

A05 방문 목록·임시 방문 확인
  목록: 예정/실제 시각, 임시 여부, 전송 상태, 검토 상태.
  임시 방문은 지원사 사유·선택 이용자 확인 후 기존 일정 연결 또는 별도 유지 [제안].
  확인 전에도 휴대폰의 원본 방문 기록은 보존한다. 거절해도 원본을 삭제하지 않음.

A06 방문·확인 사건 상세 — 핵심
  상단: 사건 ID·방문 ID, 이용자/지원사, 검토 상태, 담당자.
  1영역: “왜 확인하나요?” 출처(규칙/AI), 구간, 관찰된 차이, 기록 품질.
  2영역: 예정 vs 실제 시간줄. 휴게는 별도 음영. 수집 누락은 빈 구간으로 표시.
  3영역: 현장 사유·답변·정정 요청 이력.
  4영역: 선택적으로 여는 경로 지도. 휴게·미측정 사이 연결선 없음.
  오른쪽 조치: 질문 작성, 담당자 배정, 기관 답변, 검토 결과, 완료 버튼.
  비활성 완료 버튼 아래 “지원사 답변이 필요합니다” 등 부족 요건 표시.
  사건 없이 일반 방문을 열면 부정 의심 문구·강제 답변 영역을 만들지 않는다.

A07 질문·기관 답변 패널
  질문: 확인 구간 자동 표시 + 구체적인 질문 작성 → 지원사에게 요청.
  답변: 지원사 답변을 확인한 후 기관 판단 근거와 결과를 입력.
  결과 예: 설명 확인 / 정정 반영 / 추가 확인 필요. ‘부정수급 확정’ 자동 선택 없음.
  완료는 쌍방 답변과 정정 처리 상태 검사 후 가능. 추가 확인 필요는 대기 상태 유지.
  검토 완료 후 중요한 정정이 승인되면 재검토 상태로 전환하고 이력 보존 [제안].

A08 일정 변경·기록 정정 승인
  원본 값/요청 값/사유/신청자/시각을 나란히 표시.
  [승인] / [사유를 적고 반려]. 승인 시 원본 보존 + 정정 버전 생성.
  분석에 영향이 있으면 관련 규칙·AI 재평가. 지원사에게 결과 통지.
  여러 관리자가 열었으면 최신 버전 확인 후 저장; 충돌 시 새 내용 확인 안내.

A09 기록 품질·운영 상태
  미수신·위치 미확보·권한 없음 구분. 마지막 수신 시각과 기기 상태 신고만 표시.
  기관 담당자에게 앱 설정 확인·지원사 연락 등 복구 행동 연결.
  서버가 알 수 없는 오프라인 휴대폰 내부 상태를 ‘정상 수집 중’으로 표시하지 않는다.

A10 기관 설정·감사 이력
  담당 관리자 권한, 알림 수신자, 보관·삭제 정책, 기록 수정·열람 이력.
  2시간/3시간 기준 변경은 버전·변경자·적용 시점 기록. 과거 알림을 몰래 바꾸지 않음.
  설정 변경 권한은 지정 관리자에게 제한 [제안]. 실증 전 기준·권한을 합의한다.

08. AI와 규칙 기반 분석 — 데이터는 판단의 근거이지 증명이 아니다
────────────────────────────────────────
입력: 해당 기관·방문 ID, 지원사, 예정/실제 시각, 휴게, 위치·정확도, 관측 시각,
      등록 주소 버전, 현장 사유, 과거 유사 방문(허용된 범위).

분기 1 | 시간 데이터
  시각·순서 검증 → 일정/실제 중복·종료 누락 후보.
  위치가 없어도 가능하다. 미전송 종료를 고려한 유예·판정 조건은 시험 후 확정.
분기 2 | 위치 데이터
  관측 시각·정확도·누락 검사 → 휴게·종료·불량 구간 제외 → 거리·체류·외출 특징 계산.
  품질이 충분한 구간만 위치 규칙과 과거 패턴 비교로 보낸다.
  통계 기준으로 시작하고 AI가 오탐·검토 시간을 실제로 개선하는지 비교한다.

R1 거주지 밖
  주소 좌표와 오차 범위·허용 반경 비교. 반경 경계면 판단 보류.
  집 밖이라는 이유 하나로 자동 사건을 만들지 않는 설계를 유지한다.
R2 장기 체류 3시간 [검증 전 시험값]
  같은 위치 부근의 양질 관측이 이어진 경우만 계산. GPS는 실내 신체 움직임을 증명하지 못함.
  3시간 재가 돌봄은 정상 가능. 절전·누락을 체류로 간주하지 않는다.
R3 거주지 밖 2시간 [검증 전 시험값]
  R1과 같은 구간이면 하나로 묶는다. 병원·장보기 등 예정된 지원과 현장 설명을 대조.
  휴게·측정 공백 양쪽 구간을 연속으로 합산하지 않는다.
M1 과거 유사 방문과 차이 [모델·표본 수 미정]
  같은 이용자·서비스 유형·시간대의 중앙값·변동 범위와 비교.
  평균보다 크다는 사실만으로 사건 생성 금지. 자료 부족은 ‘분석 준비 중/판단 보류’.
  휴대폰 GPS만으로 활동지원사가 실제 무슨 행동을 했는지 분류한다고 주장하지 않는다.

사건 생성 [제안]
  분석 후보 → 품질/예외 검토 → 담당자에게 확인 가치가 있는 후보만 사건 생성.
  한 방문의 같은 시간대·같은 원인 후보는 하나로 묶는다. 같은 경고를 매 좌표마다 보내지 않음.
  사건에 기록: 탐지 출처, 대상 구간, 근거 값, 품질, 기준·모델 버전, 생성 시각, 담당자.
  추론 불가·서버 오류는 품질 상태로 저장. 오류를 고위험으로 바꾸지 않음.
  AI 작동/규칙만 작동/자료 부족을 관리자 화면에서 구분한다.
  첫 시제품 학습·시험에는 가상/동의 받은 테스트 자료 사용. 운영 자료 자동 학습은 제외.
  관리자 검토 완료를 ‘진짜 부정/정상’ 정답으로 자동 학습하지 않는다.

알림 설계 [제안]
  AI 확인 사건 → 기관 웹 알림함 및 담당자 알림. 지원사에게는 관리자 질문이 도착할 때 알림.
  잠금화면 문구: “기관에서 확인 요청이 도착했어요.” 이용자 이름·주소·경로는 숨김.
  앱 알림 거부/푸시 실패에도 요청함에 남는다. ‘발송’과 ‘열람’과 ‘답변’을 별도 상태로 관리.
  미응답 재안내 시간·횟수와 비상 대응은 미정. AI 알림을 안전 긴급출동 서비스로 표현하지 않음.

09. 데이터가 이동하는 과정
────────────────────────────────────────
① 기관이 일정 배정
  웹 → 서버 권한 확인 → 기관별 일정 저장 → 지원사 앱에 배정 일정·필요 이용자 정보 동기화.
② 지원사가 버튼 누름
  앱 → 기기 저장 성공 → 화면 상태 변경 → 전송 대기 목록 → 서버.
  기기 저장 실패는 “기록하지 못했어요”로 알려 성공한 것처럼 표시하지 않는다.
③ 위치 측정
  돌봄 중·허용 권한·측정 가능 시 위치 이벤트 저장. 휴게·종료 때 수집과 저장 조건 모두 차단.
  수집 주기/배치 전송은 실기기 시험으로 확정. 연결 끊김과 GPS 불량을 구분한다.
④ 서버 수신
  사용자·기관·방문 권한 확인 → 고유 이벤트 ID 중복 제거 → 원본 저장 → 성공 응답.
  기기는 응답 후 전송 완료 표시. 응답이 유실돼 재전송해도 한 번만 저장한다.
⑤ 방문 계산·분석
  기록 발생 시각·순서로 재구성. 서버 도착 순서만으로 휴게/복귀를 계산하지 않는다.
  늦게 도착한 기록에 따라 관련 구간만 재평가하고 기존 판단 이력을 유지한다.
⑥ 기관 요청·지원사 답변
  사건 ID에 질문 저장 → 앱 요청함 → 지원사 답변 기기 저장 → 서버 → 기관 답변·검토 결과.
⑦ 정정
  요청 값 + 사유 → 관리자 승인 → 새 해석 버전 → 필요 시 분석 재평가.
  원본 버튼·좌표 시각은 삭제·덮어쓰기하지 않는다.

주요 데이터 묶음
  계정·기관 소속: 계정 ID / 기관 ID / 역할 / 연결·해제 이력.
  이용자·주소: 기관 내 이용자 ID / 최소 정보 / 주소 버전 / 담당 관계.
  일정: 일정 ID / 기관 / 대상 / 지원사 / 예정 구간 / 휴게 / 수정 버전.
  방문: 방문 ID / 일정 ID 또는 임시 연결 / 담당 / 현재 상태.
  이벤트: 이벤트 ID / 종류 / 기기 발생 시각 / 서버 수신 시각 / 순번 / 원본.
  위치: 방문 ID / 측정 시각 / 좌표 / 정확도 / 유효 여부.
  현장 설명: 방문·구간 / 선택 사유·메모 / 작성자 / 시각 / 수정 이력.
  확인 사건: 출처·근거·기준 버전 / 질문 / 지원사 답변 / 기관 답변 / 검토 결과.
  정정 요청: 원본 참조 / 요청 값 / 사유 / 승인자·결과 / 승인 시각.
  알림·감사: 수신 대상 / 발송·열람 / 민감정보 열람·수정 이력.

보호·정합성 설계
  기관 ID를 서버에서 검증한다. 화면 필터만으로 기관 분리를 구현하지 않는다.
  기기 저장 보호·통신 보호·백업·삭제 정책과 계정 탈퇴 시 미전송 처리 필요.
  기기 시계 변경·재부팅 시각 불일치 감지와 안내를 설계한다. 원격 서버 시각만으로
  오프라인 기록을 대체하지 않고, 불확실한 구간은 검토 대상으로 분리한다.
  동일 계정 여러 기기·동시 시작은 서버 검증 및 충돌 검토가 필요.
  오프라인 다른 기기의 동시 시작까지 완전히 차단했다고 주장하지 않는다.
  같은 사람의 다른 기관 기록은 현재 범위에서 교차 열람·분석하지 않는다.

10. 화면과 데이터가 함께 맞는지 확인하는 시험
────────────────────────────────────────
T01 가입 후 기관 미등록: 오늘 방문 이용 불가·대기 안내. 기관 확인 후 본인 일정만 표시.
T02 타 기관 계정이 방문 URL 직접 접근: 데이터 응답 거부. 이용자 검색도 타 기관 결과 없음.
T03 정상 방문: 예시 4시간 30분 중 휴게 30분, 돌봄 기록 4시간이 앱/웹에서 일치.
T04 휴게 중 종료: 휴게 구간 종료, 위치 저장 없음, 불필요한 복귀 기록 생성 안 됨.
T05 위치 거부: 시작·시간 기록 가능, ‘위치 없음’. AI 경로 분석 보류.
T06 오프라인 종료: 즉시 위치 중단, 재접속 시 이벤트 한 번만 저장, 발생 시각 유지.
T07 임시 방문: 등록 이용자만 선택, 기관에 임시 표시, 정식 일정과 이중 집계 안 됨.
T08 휴게/종료 버튼 실수: 사유 있는 정정 요청, 승인 전 원본 유지, 승인 후 이력·합계 갱신.
T09 정상 장기 체류·병원 동행: 단일 조건만으로 부정 판정·과도한 설명 요청 없음.
T10 GPS 미수신: 3시간 무움직임으로 오인 안 됨. 시간 중복 점검은 가능한 데이터로 수행.
T11 확인 사건: 지원사 답변만 있고 기관 답변 없으면 완료 불가. 반대 경우도 불가.
T12 답변 오프라인: 초안·전송 대기 표시. 기관은 아직 미수신 상태. 복구 후 중복 없이 반영.
T13 알림 미허용: 푸시 없어도 요청함에서 사건 확인 가능.
T14 검토 완료 후 정정: 과거 결과 보존, 관련 사건 재평가·재검토 상태 제시.
T15 두 관리자의 동시 승인: 최신 상태 확인, 승인/반려가 동시에 적용되지 않음.
T16 작은 화면·확대 글씨: 시작/휴게/종료 버튼 안 겹침, 상태가 색상 없이도 읽힘.
T17 실기기: Android/iOS의 잠금·절전·앱 재실행·권한 변경을 따로 재현.
T18 현장 설명: 본인 진술과 자동 측정 표시 분리, 진술을 방문 증명으로 오인하지 않음.

11. 핵심 기능 구현 순서
────────────────────────────────────────
1단계: 기관 분리·가입/연결·대상/일정·방문 상태·휴게·시간 기록.
2단계: 임시 방문·오프라인/백그라운드 위치·수집 품질·승인 정정·양쪽 화면 상태 연결.
3단계: 규칙 및 AI 후보·기관 알림·지원사와 기관의 답변·완료 조건.
4단계: 오탐/누락/배터리/이해도 시험. 자료가 충분하지 않으면 AI 효과를 확정하지 않음.
다기관·두 운영체제·기관 답변은 최종 핵심 범위다. 단계 분리는 구현 순서이며 범위 제외가 아니다.

12. 다음에 확인할 사항 — 결정 전에도 위 설계와 가상 시연은 가능
────────────────────────────────────────
높은 우선순위
  • 온라인 알림 목표는 조건 충족 후 2~5분, 수신자는 관리자만으로 확정. 실측 검증 필요.
  • 기관 계정 개설/관리자 초대와 지원사 기관 연결 코드 방식.
  • 임시 방문의 기관 사후 확인 절차, 같은 앱에서 동시 방문 시작 차단 여부.
  • 기관 이동 때 이전 기록·미전송 건·미완료 답변 처리.
  • 지원사가 답변 불가능한 장기 미응답 사건의 운영 절차. 현재는 자동 종결 불가.
실증 전
  • 등록 거주지 허용 반경, GPS 품질 기준, 표본 수, 알림 기준·재알림 간격.
  • 기록 보관·삭제 기간, 계정 복구/시계 변경/다중 기기 정책, 열람 범위.
  • Android/iOS 실제 시험 기종과 기관 담당자, 참여자 모집.
  • 선택형 현장 설명 항목과 용어를 실제 지원사에게 확인.
