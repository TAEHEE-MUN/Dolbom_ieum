동행이음 | 디자이너 전달 03. 기관 관리자 웹 와이어프레임
작성일 2026-11-19 / 기획 v1.2 기준 / 전달본 1.0
대상: 기관 담당 관리자, Windows·Mac 브라우저. 자기 기관 자료만 열람한다.
A01~A10은 설계 단위10개. A07은 A06 내부 패널로 가능. 변형·입력창은 별도 제작.

1. 주요 경로
────────────────────────────────────────
기관 준비: A01 → A03 직원/이용자 등록 → A04 일정 → A02 현황.
검토: A02 확인 목록 → A06 근거 → A07 질문 → 지원사 앱 답변 → A07 기관 답변·결과.
정정: A08 원본/요청 비교 → 승인 또는 사유 반려 → 앱 결과 → 관련 사건 재평가.
품질: A02 품질·지연 안내 → A09 확인 → 복구 안내. 자동 부정 판정으로 연결하지 않는다.

2. 대시보드 배치와 상호작용
────────────────────────────────────────
상단: 기관명 / 관리자 / 알림함 / 마지막 갱신 시각.
좌측: 현황, 일정, 방문 기록, 확인 사건, 변경 요청, 지원사·이용자, 기관 설정.
본문1행: 날짜·담당자·방문 상태·검토 상태 필터, 초기화.
본문2행: 예정/돌봄 중/쉬는 중/종료 카드 → 클릭 시 해당 목록 필터.
본문3행: 확인 사건 총수와 답변 대기 등 업무 상태. 겹치는 수를 합산하지 않는다.
주요 표: 방문·지원사 / 이유·출처 / 구간 / 검토 상태 / 담당자 / 상세 보기.
품질·마지막 수신 등 보조 열은 펼침이나 상세로 제공해 과밀한 표를 피한다.
보조 목록: 임시 방문, 수신 지연, 정정 승인 대기. 반복 정정은 운영 개선으로 분리.
빈 상태: ‘확인할 기록이 없습니다’. 서버 오류를 정상0건으로 표시하지 않는다.

3. 근거 상세 화면의 최신 요구
────────────────────────────────────────
누가/언제 → 왜 확인하는지 한 문장 → 구간 → 기록 품질 → 현장 설명 → 다음 행동.
출처 배지: 규칙 / AI 후보 / 센서 시험 / 데이터 품질 / 운영 개선.
거주지 밖2시간, GPS체류3시간, 움직임미관측2시간은 서로 다른 항목이다.
센서 문구: ‘휴대폰 움직임이 장시간 관측되지 않았습니다. 현장 상황 확인이 필요합니다.’
‘지원사 외출 확인’이라고 표시하지 않는다. 센서 공백은 판단 불가.
AI 비교에는 비교 기간·자료 수·관측 차이를 보여준다. 자료 부족 시 분석 준비 중.
부정 확률·정확도·직원 위험 순위는 임의로 넣지 않는다.
시간줄은 예정/실제/휴게/관측 공백/확인 구간을 문자·패턴으로 구분한다.
지도는 선택적으로 펼친다. 관측 누락·휴게 사이에 실제 이동처럼 연결선을 그리지 않는다.
현장 설명은 본인 작성, 위치·시각은 측정 정보임을 구분한다.

4. 화면별 상세 명세
07. 관리자 웹 와이어프레임 명세
────────────────────────────────────────
공통: 상단 기관명·계정·알림. 왼쪽 메뉴는 현황 / 일정 / 방문 기록 / 확인 사건 /
      변경 요청 / 지원사·이용자 / 기관 설정.
      다른 기관으로 이동 가능한 일반 기관 계정을 만들지 않는다.
      지도 중심의 상시 감시 화면보다 확인할 업무 목록을 먼저 보여준다.

A01 관리자 로그인·기관 진입
  기관 계정으로 로그인, 자기 기관 홈으로 이동. 기관 개설/관리자 초대 절차는 미정.
  권한 없는 URL 직접 접근도 서버에서 거부한다.

A02 오늘의 현황 — 대시보드
  상단 필터: 날짜·담당자·기록 상태·검토 상태.
  첫 줄 카드: 예정 / 돌봄 중 / 쉬는 중 / 종료. 한 방문은 이 중 하나에만 포함.
  두 번째 카드: 확인 사건 / 지원사 답변 대기 / 기관 답변 대기 / 정정 승인 대기.
  ‘확인 사건’은 방문 건수와 다른 집계임을 표시. 하위 상태를 전체 합계와 중복 합산하지 않음.
  중앙 주요 표: 시각, 지원사, 이용자, 탐지 출처, 이유, 구간, 품질, 마지막 수신, 담당자, 상태.
  보조 표: 임시 방문과 기록 수신 지연. 경로 판단 보류는 부정 의심 건수에 넣지 않음.
  행동: 행 선택 → A06, 임시 방문 → A05, 정정 요청 → A08.

A03 지원사·이용자 관리
  지원사 탭: 등록 코드 확인, 연결 대기/활성/해제 상태, 담당자 배정.
  이용자 탭: 최소 식별정보, 등록 거주지, 담당 지원사, 활동 가능 범위 관련 메모.
  버튼: [지원사 등록], [이용자 등록], [담당자 변경].
  기관명이 다른 연결 요청은 막는다. 주소 변경 이력을 남겨 과거 방문을 새 주소로 재판정하지 않음.

A04 일정 달력·편집
  일/주 보기, 지원사별 시간 막대, 휴게 예정, 일정 충돌 안내.
  입력: 등록 이용자·지원사·날짜·시간·예정 휴게·기관 메모.
  예정 일정 충돌은 배정 경고이고 실제 방문 중복 사건과 구분.
  시작 후 일정 변경은 새 버전으로 남긴다. 실제 기록 원본은 바꾸지 않는다.
  지원사 변경 요청 승인/반려 → 앱에 새 일정 수신 여부 표시.

A05 방문 목록·임시 방문 확인
  목록: 예정/실제 시각, 임시 여부, 전송 상태, 검토 상태.
  임시 방문은 지원사 사유·선택 이용자 확인 후 기존 일정 연결 또는 별도 유지 [제안].
  확인 전에도 휴대폰의 원본 방문 기록은 보존한다. 거절해도 원본을 삭제하지 않음.

A06 방문·확인 사건 상세 — 핵심
  상단: 사건 ID·방문 ID, 이용자/지원사, 검토 상태, 담당자.
  1영역: “왜 확인하나요?” 출처(규칙/AI), 구간, 관찰된 차이, 기록 품질.
  2영역: 예정 vs 실제 시간줄. 휴게는 별도 음영. 수집 누락은 빈 구간으로 표시.
  3영역: 현장 사유·답변·정정 요청 이력.
  4영역: 선택적으로 여는 경로 지도. 휴게·미측정 사이 연결선 없음.
  오른쪽 조치: 질문 작성, 담당자 배정, 기관 답변, 검토 결과, 완료 버튼.
  비활성 완료 버튼 아래 “지원사 답변이 필요합니다” 등 부족 요건 표시.
  사건 없이 일반 방문을 열면 부정 의심 문구·강제 답변 영역을 만들지 않는다.

A07 질문·기관 답변 패널
  질문: 확인 구간 자동 표시 + 구체적인 질문 작성 → 지원사에게 요청.
  답변: 지원사 답변을 확인한 후 기관 판단 근거와 결과를 입력.
  결과 예: 설명 확인 / 정정 반영 / 추가 확인 필요. ‘부정수급 확정’ 자동 선택 없음.
  완료는 쌍방 답변과 정정 처리 상태 검사 후 가능. 추가 확인 필요는 대기 상태 유지.
  검토 완료 후 중요한 정정이 승인되면 재검토 상태로 전환하고 이력 보존 [제안].

A08 일정 변경·기록 정정 승인
  원본 값/요청 값/사유/신청자/시각을 나란히 표시.
  [승인] / [사유를 적고 반려]. 승인 시 원본 보존 + 정정 버전 생성.
  분석에 영향이 있으면 관련 규칙·AI 재평가. 지원사에게 결과 통지.
  여러 관리자가 열었으면 최신 버전 확인 후 저장; 충돌 시 새 내용 확인 안내.

A09 기록 품질·운영 상태
  미수신·위치 미확보·권한 없음 구분. 마지막 수신 시각과 기기 상태 신고만 표시.
  기관 담당자에게 앱 설정 확인·지원사 연락 등 복구 행동 연결.
  서버가 알 수 없는 오프라인 휴대폰 내부 상태를 ‘정상 수집 중’으로 표시하지 않는다.

A10 기관 설정·감사 이력
  담당 관리자 권한, 알림 수신자, 보관·삭제 정책, 기록 수정·열람 이력.
  2시간/3시간 기준 변경은 버전·변경자·적용 시점 기록. 과거 알림을 몰래 바꾸지 않음.
  설정 변경 권한은 지정 관리자에게 제한 [제안]. 실증 전 기준·권한을 합의한다.


5. 검토 완료와 상태 변형
────────────────────────────────────────
지원사 답변 + 기관 답변 + 검토 결과 + 필요한 정정 처리 완료가 있어야 사건 완료 가능.
완료 버튼 아래 부족한 항목을 안내. 정상 방문 전체에 답변을 요구하지 않는다.
질문 전 오탐 사건을 닫는 방법은 미정이므로 임의 자동 종결 버튼을 확정하지 않는다.
A03 등록 폼·연결 확인·중복 소속 / A04 생성·편집·충돌 / A05 임시 방문 연결 패널.
A06 일반 방문·자료 부족·센서 미지원·위치 품질 불량·통신 지연 변형.
A07 질문 작성·답변 대기·답변 도착·기관 답변 미작성·완료 불가·저장 완료.
A08 승인 확인·반려 사유·다른 관리자가 처리한 충돌 / A09 복구 안내.
공통: 로딩·빈 검색·서버 오류·재시도·접근 거절·세션 만료·입력 초안 보존.

6. 갱신과 프로토타입 검수
────────────────────────────────────────
온라인 조건 충족 후 관리자 표시까지2~5분 목표. 무조건 실시간이라는 문구는 사용하지 않는다.
새 기록이 와도 작성 중인 질문 폼을 초기화하지 않는다. 목록 갱신 안내를 제공한다.
오프라인은 마지막 수신 시각 표시. 현재도 돌봄 중이라고 단정하지 않는다.
알림 발송/열람/지원사 답변을 구분. 지원사는 관리자 질문 이후 요청을 받는다.
늦게 도착한 기록·승인 정정으로 바뀐 판단은 이전 결과와 변경 시각을 보존한다.
검수: 지도 없이 이유 파악 가능한가? GPS불량이어도 시간 중복을 확인할 수 있는가?
쌍방 답변 미충족 이유가 보이는가? 승인/반려 결과가 앱에 연결되는가?
폰 정지를 지원사 외출로 단정하지 않는가? 동일 사건이 여러 건처럼 중복 집계되지 않는가?
최종 전달: A01~A10 및 패널·상태 변형, 공통 컴포넌트, 클릭 경로, 미정 정책 주석.
