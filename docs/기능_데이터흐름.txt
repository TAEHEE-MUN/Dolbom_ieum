동행이음 | 현재 코드의 기능·데이터 흐름 | 2026-11-21

[확정 정책]
휴대전화 SMS 인증. 실제 발송 설정은 보류.
한 지원사는 동시에 한 기관에만 소속.
운영자가 기관·최초 관리자 등록. 기관 관리자가 지원사 연결·이용자 배정.
임시 방문은 본인에게 배정된 등록 이용자만 선택.
일정은 관리자가 변경하고 지원사는 사유와 함께 변경을 요청.
동일 앱에서 방문 동시 진행 차단. 여러 기기 간 겹침은 서버 검토 후보.
AI 후보는 관리자만 먼저 확인. 관리자가 질문을 보내면 지원사에게 노출.
검토 완료에는 지원사 답변·기관 담당자 답변·미처리 정정 해소가 필요.

[활동지원사 앱]
1. 휴대전화 인증 → 이름·안내 확인 → 위치 기록 동의 선택.
2. 연결 코드를 기관에 전달 → 기관 연결 요청 수락.
3. 오늘 배정된 방문 → 방문 상세 → 시작 또는 일정 변경 요청.
4. 서비스 시작 → 휴대폰 SQLite에 시작 시각 저장 → 허용한 경우 위치 스트림 시작.
5. 돌봄 중 → 쉬기 시작 → 위치 중단 및 휴게 시각 저장.
6. 다시 시작 → 복귀 저장·위치 재개.
7. 종료 확인 → 위치 중단 → 종료 저장 → 전체·돌봄·휴게 시간 표시.
8. 기록 → 날짜·시간 선택기로 정정 신청 → 사유 → 기관 승인 대기.
9. 요청 → 기관의 질문 확인 → 짧은 답변 → 전송 대기 또는 전달 완료.
큰 글씨·큰 버튼·황색 주요 행동과 어두운 글자. 상태는 색 외에 문자로 표시.
휴게는 실제 버튼 기록 기준. 30분을 자동 공제하거나 자동 복귀하지 않음.
원본 시간은 자동 삭제·덮어쓰기하지 않음. 계산값은 급여·결제 확정값이 아님.

[관리자 웹]
기관 로그인 → 오늘 현황 → 지원사 연결·이용자 등록·배정 → 일정 등록.
방문 기록은 상태·이용자 검색으로 찾고, 상세에서 원본 타임라인·현장 설명·위치 관측표 확인.
확인 사건은 품질 / 규칙 / AI / 운영 유형 구분.
기관 담당자 질문 → 지원사 답변 → 기관 답변 및 검토 결과 저장.
변경 요청 화면에서 일정 변경 승인·반려. 방문 상세에서 시간 정정 승인·반려.
정정 승인 시 기존 사건의 검토를 다시 열고 이전 답변은 감사 이력에 보관.
기관 설정에서 전체 패턴 점검 및 감사 이력 조회.
관리자 웹이 열린 활성 탭에서는 2분 주기로 점검 요청. 닫힌 브라우저를 대신하는 상시 서버 작업은 아직 없음.

[오프라인 데이터 흐름]
시각/위치 → 기기별 SQLite → UUID·순서번호가 포함된 API 요청 → Supabase RPC 검증 → PostgreSQL.
미전송 기록은 먼저 휴대폰에 저장. API 실패를 전송 성공으로 처리하지 않음.
통신 복구 후 앱 실행 중 60초 주기·새로고침·기록 이벤트를 통해 재전송.
동일 이벤트는 재전송해도 중복 생성하지 않으며 동일 ID 내용 변조는 거절.
휴게/종료는 통신 응답보다 먼저 위치를 중단.
기기 전원 꺼짐·강제 종료 뒤 자동 수집/전송은 보장하지 않음.
재실행 시 사용자가 위치 기록 재시작 버튼으로 재개. 비수집 구간은 보간하지 않음.

[분석 순서]
1. 승인 정정으로 유효 시간 구성(원본 별도 보존).
2. GPS 정확도·부족·구간 누락 확인. 휴게 구간 제외.
3. 외출 2시간·유사 위치 체류 3시간 시험 규칙.
4. 일정 차이·동일 지원사 겹침·종료 미수신·이동 시간 모순·경계 반복 출입·시작/종료 부근만 거주지·반복 정정 후보.
5. 같은 이용자의 이전 종료 방문 중 품질 조건을 충족한 자료가 20건 이상일 때 기록 시간 기반 IsolationForest 비교.
6. 코드·분석 버전·근거·시간 구간을 저장 → 관리자가 검토.
현재 AI 입력은 기록 시간 중심이며 완성된 행동 인식 모델이 아님.
2시간 휴대폰 무움직임은 센서 실험 항목으로 남겨둠. GPS 체류와 동일하지 않으며 외출의 증거로 표시하지 않음.
기존 후보는 탐지 당시 근거를 보관하는 방식. 재분석에서 미검출되어도 자동 무혐의/자동 사건 삭제하지 않음.

[DB 접근]
public 테이블 RLS 사용. 지원사 본인 방문, 관리자 소속 기관 범위로 조회.
인증 사용자의 직접 테이블 쓰기 차단. app_command RPC에서 상태·역할·기관·소유자 검증.
일반 사용자 메타데이터로 관리자 권한을 부여하지 않음.
기관·최초 관리자 등록은 운영자 전용 SQL 함수. 앱/웹에 service_role 키 없음.
